# UI Guidelines · 药箱管家 MediBox

> 本文件规定「页面怎么组合」「状态怎么呈现」「文案怎么写」「动画怎么动」「审查怎么过」。与 `DESIGN_SYSTEM.md` 配套，是 UI 评审与实现的硬性约束。

---

## 1. 反 AI 审美原则（最高优先级）

- 用户第一眼的感觉必须是：「这是一个很好用的家庭药箱工具」，而不是「这是 AI 做的 Demo」。
- 高级感来自**排版、留白、比例、间距、层级、字体、颜色、交互**，不来自任何视觉装饰。
- **不要为了"高级感"而增加视觉元素。** 每加一个元素，先问「删掉会更好吗？」
- 我们的"签名细节"（让产品显出人手调过）：暖纸背景、系统中文默认字体、发丝分隔线、极大留白、单一克制品牌绿、人话空状态、几乎无感的动效。

---

## 2. 页面构图模板

所有内容页遵循同一骨架，保证一致性与可预期：

```
┌─────────────────────────────┐
│  TopBar（标题左 / 动作右）    │  ← 无底色、无阴影，仅底部 1dp divider
├─────────────────────────────┤
│                             │
│   内容区（screenPaddingX=20） │  ← 可滚动；首屏上方 space6~space8 留白
│                             │
├─────────────────────────────┤
│  BottomNav（5 项）            │  ← 仅顶部 1dp divider 上沿
└─────────────────────────────┘
```

规则：
- 每页**一个明确目标**，不堆多功能。首页是例外（概览），但仍保持克制。
- 内容区纵向流：先最重要的信息/操作，再次要。用 `sectionGap(24)` 分段，不用卡片包裹每段。
- 列表优先用 `AppListItem` + `divider`，**不**每行套 Card。
- 大数字/关键操作可适度突出，但全屏不超过 1 个视觉焦点。

## 3. 状态模式（每个主页面必备）

> 状态是产品与用户沟通的机会，必须"说人话"，禁止营销腔与机械报错。

### 3.1 Empty State（空状态）
- 居中：线性图标(`inkTertiary`) + 标题(`titleSmall`) + 一行说明(`secondary`) + 主操作按钮。
- 文案示例：
  - 药箱空：「你的药箱还是空的」/「扫描第一件药品，几秒就能记下来。」
  - 搜索无结果：「没有找到相关药品」/「换个关键词，或扫描新药盒。」
- **禁止**：「欢迎使用我们的智能药品管理平台！」之类 AI 文案。

### 3.2 Loading State（加载）
- 居中细 spinner（`inkSecondary`），下方可选一行 `secondary` 说明。
- 列表首次加载可用骨架行（同 `AppListItem` 高度，`surfaceVariant` 占位），**不用花哨 shimmer**（若有，仅极轻透明度脉冲，≤200ms）。
- 不阻塞操作；能异步就异步。

### 3.3 Error State（错误）
- `ErrorOutline`(`danger`) + 一句人话（`secondary`）+ 重试按钮。
- 文案示例：「药品读取失败了」/「网络或存储出了问题，点这里重试。」
- 不抛原始异常；不出现红色全屏恐慌。

### 3.4 Success State（成功）
- 对勾(`ok`) + 一句确认（`secondary`），**短暂展示（~1.2s）后自动消失**或返回上一页。
- 示例：「已保存到药箱」「库存已更新」。
- 不用弹窗庆祝、不用彩带。

### 3.5 Permission State（权限）
- 说明"为什么需要"+ 去授权按钮；拒绝后仍留在可用页面（引导手动录入/稍后授权）。
- 相机：「药箱管家需要相机来扫描药盒。」/ 按钮「允许使用相机」。
- 通知：「开启后，药品临期会提醒你。」/ 按钮「开启提醒」。
- **绝不**因权限拒绝而让 App 不可用。

### 3.6 OCR Failed State（识别失败）
- 说明 OCR 未识别出文字 + 「手动录入」按钮（**保留主路径**）。
- 文案：「没看清包装上的字」/「你可以直接手动填写药品信息。」
- 不等、不转圈、不报错色（用中性 `secondary`）。

## 4. 文案规范（Voice & Tone）

- 语气：自然、简洁、像人在说话；不卑不亢。
- **禁用词**：智能、AI、赋能、魔法、全自动、革命性、下一代、重新定义、AI 驱动、平台、解决方案、智能识别。
- 动词优先、名词克制：
  - 「扫描药品」而非「AI 智能识别您的药品」
  - 「库存」而非「智能库存管理」
  - 「临期提醒」而非「智能预警中心」
  - 「保存」而非「一键智能归档」
- 按钮文案用动作：「扫描药品」「保存」「添加药品」「手动录入」「去授权」。
- 空状态用第二人称、带一点温度但不谄媚。
- 数字用阿拉伯数字；日期用 `yyyy-MM-dd` 或 `yyyy年M月d日`（中文语境优先后者展示，存储用前者）。

---

## 5. 动效规范

- 全局统一缓动 `Standard`(easeOutCubic)，时长 `durationFast(150)` / `durationNormal(200)`。
- 页面进入：内容 `fadeIn` + `slideUp(16dp)`，≤200ms。
- 弹层/对话框：`scaleIn(0.96→1)` + `fadeIn` + `scrim` 渐显。
- 列表项出现：可逐个 `fadeIn`（间隔 ≤40ms），不堆叠动画。
- 按压反馈：底色变化（`brandSoft`/`surfaceSunken`）+ 可选 `scaleIn 0.98`，无阴影弹跳。
- **禁止**：弹跳、弹簧过冲、粒子、发光、旋转、循环动画、页面级大位移。

---

## 6. 图标规范

- 统一 `Icons.Outlined`，线性、细描边、24dp。
- 单页图标（不含底部导航）≤ 3 个；导航图标 5 个。
- 默认 `inkSecondary`；选中/激活 `brand`；危险 `danger`；临期 `warning`。
- **禁止 Emoji 作图标**、禁止彩色填充图标、禁止装饰性图标。

---

## 7. 间距与节奏

- 屏幕左右 `screenPaddingX = 20`；内容纵向 `sectionGap = 24`。
- 列表行内纵向 `listRowVertical = 14`，行内元素间隙 `space3(12)`。
- 首页首屏上方留白 `space8(40)`，营造"呼吸感"。
- 同组元素间距小于跨组元素间距（近者更近、远者更远），形成视觉分组。
- 不把内容贴边；不把大段文字拉满整行（控制行长）。

---

## 8. 颜色纪律（再强调）

- 品牌绿面积 < 8%；只用于主按钮、选中、扫描按钮、关键链接。
- 状态色只出现在状态：过期=danger，临期=warning；"正常/在库"中性。
- 背景层次靠 `paper`/`surface`/`surfaceVariant` + `divider`，不靠阴影与彩色。
- 禁止渐变、半透明彩色、玻璃、霓虹。

---

## 9. 评审清单（每完成一页必过）

1. 看起来像 AI 自动生成吗？
2. 看起来像 Material Demo 吗？
3. 看起来像模板 App 吗？
4. 是否存在过度 Card？
5. 是否存在过度圆角？
6. 是否存在无意义装饰？
7. 是否可以删除 10% 的视觉元素？
8. 是否可以减少颜色？
9. 是否可以减少组件？
10. 如果隐藏项目名称，是否仍像一个成熟的商业 App？

任一回答不理想 → **直接修改，不解释、不保留不成熟设计**。

---

## 10. 与实现的关系

- `DESIGN_SYSTEM.md` = Token 与组件原语（"有什么"）。
- 本文件 = 组合与纪律（"怎么用、什么不许"）。
- `UI_REVIEW.md` = 逐页设计决策（"每个页面长什么样、为什么"），是设计稿与实现的桥。
- 工程侧：`ui/theme` 落地 Token；`ui/components` 落地 §8 组件；业务页面**只**组合这些，不新造视觉语言。
